How it works

A build you can see inside.

A Jenkinsfile is code with conditions in it. PipeDraft runs that code against the builds you care about, so the cause and the effect sit on the same screen.

  1. 1.0 Paste

    Bring your Jenkinsfile

    Declarative or scripted. Syntax and structure are checked as you type, the way Jenkins checks them before a build starts.

  2. 2.0 Describe

    Pick the builds

    A push to main, PR #42, tag v1.2.0, the nightly cron run. Each context sets the branch, changed files, parameters and cause.

  3. 3.0 Run

    Press Run

    Every build is simulated at once. Commands are mocked and succeed, unless you add a rule that makes one fail.

  4. 4.0 Read

    See why

    Click a stage: the when conditions, their values in this build, the steps that ran and the post blocks that fired.

FAQ

Questions, answered plainly.

Does it run Jenkins?

No. PipeDraft has its own Groovy parser and interpreter and a model of how declarative pipelines run: the when evaluation order, “skipped due to earlier failure(s)”, parallel branches and failFast, matrix cells, and the order of post conditions. It is a model you can learn from and test against. It does not replace a real build.

What happens to sh, docker and deploy commands?

Nothing is executed. Every command is mocked and succeeds, and git commands return plausible output. A mock rule in a run context makes a command fail, return specific output, or fail only the first N times.

What about shared libraries and plugins?

Common plugin steps are built in: credentials, docker, junit, input, slackSend, httpRequest, build and more. Steps PipeDraft does not know, including those from a @Library, are mocked as successful no-ops and flagged, so you can see where they are called. The limits are listed in the README.

Why is there a Run button instead of live results?

Syntax and structure checks are live, because they are cheap and you want them while you type. A run simulates every context at once and animates the build, so you decide when it happens: press Run or ⌘/Ctrl + Enter. If you prefer live results, switch on Auto-run.

Does my Jenkinsfile leave my browser?

No. Everything runs on your device and there is no backend. The only exception is a share link you create yourself: it contains your Jenkinsfile, compressed into the URL.

Is it free and open source?

Yes, both. The code is on GitHub. Issues, examples and corrections are welcome.
